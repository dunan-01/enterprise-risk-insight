> 状态：Active

> 适用范围：所有企业风险调查报告（C001-C010 及未来扩展）

## 1. 报告定位

### 1.1 报告是什么

本报告是**企业关联风险智能洞察系统**的唯一输出物。它是一份面向风控决策者的风险调查报告，回答一个核心问题：

> **这家企业的整体风险状况如何？应该关注什么？**

### 1.2 报告不是什么

- 不是企业档案（不罗列工商基本信息）
- 不是财务分析报告（不展示完整财务数据表）
- 不是法律意见书（不替代专业法律、审计或授信决策）
- 不是投资建议（不提供买卖推荐）
- 不是数据_dump（不罗列所有查询到的 Evidence）

### 1.3 报告的数据基础

报告基于六大类多源数据：

| 数据源 | 代号 | 典型内容 |
|--------|------|----------|
| 工商 | B | 行政处罚、经营异常、股权冻结、重要工商变更 |
| 司法 | J | 诉讼、被执行、失信被执行、限制消费、股权冻结 |
| 企业关系 | R | 股权、对外投资、共同法人、共同股东、担保 |
| 舆情 | P | 负面舆情（已核实/未核实）、正面信号 |
| 财务 | F | 营收、利润、现金流、负债率、审计意见 |
| 招聘 | H | 岗位变化、招聘冻结、扩张信号 |

### 1.4 风险等级的唯一 Source of Truth

报告中的**综合风险等级、综合风险评分、风险模式（Case）、风险解释**由后端确定性引擎计算，不由 LLM 自行指定。

```
计算链路：
Rule Engine (own_risk)
  + Transmission Engine (relationship_exposure)
  + Fusion Engine (comprehensive_risk)
  → report_postprocessor 注入报告
```

LLM 的职责是：发现风险事实、绑定 Evidence ID、给出风险分析文本。风险等级和评分为确定性注入，LLM 不需要也不允许在报告中自行指定。

## 2. 固定一级章节

报告必须包含以下八个一级章节，顺序固定，不可省略、不可调换、不可合并：

| 序号 | 章节名称 | 必须存在 | 说明 |
|------|----------|----------|------|
| 一 | 风险结论摘要 | ✅ | 开篇结论，1-2 段 |
| 二 | 企业自身主要风险 | ✅ | 动态二级章节（见 §3） |
| 三 | 关联企业及风险传导 | ✅ | 关联风险逐企业展开 |
| 四 | 多源证据综合分析 | ✅ | 交叉验证，非罗列 |
| 五 | 风险缓释因素与矛盾信号 | ✅ | 呈现反面证据 |
| 六 | 综合风险判断 | ✅ | 最终结论 + 确定性注入 |
| 七 | 证据限制与不确定性 | ✅ | 事实/推断/未核实区分 |
| 八 | 关键证据引用 | ✅ | 仅支撑判断的 Evidence |

### 2.1 一级章节的 Markdown 格式

```markdown
## 一、风险结论摘要
...
## 二、企业自身主要风险
...
## 三、关联企业及风险传导
...
## 四、多源证据综合分析
...
## 五、风险缓释因素与矛盾信号
...
## 六、综合风险判断
...
## 七、证据限制与不确定性
...
## 八、关键证据引用
...
```

### 2.2 一级章节之间的分隔

每个一级章节之间使用 `---` 分隔（水平线），保持报告的视觉清晰度。

## 3. 动态风险章节规则

### 3.1 第二章：企业自身主要风险

第二章的二级小节是**动态生成**的，规则如下：

**生成规则：**
- 仅为存在 Material Risk Evidence 的类别生成二级小节
- 编号按实际输出顺序顺排（如只有财务与司法，则为 2.1 财务、2.2 司法）
- 禁止为"凑完整"而输出"未发现……"的空章节

**可选的二级小节类别：**

| 类别 | 触发条件 | 不触发条件 |
|------|----------|------------|
| 工商与经营风险 | 行政处罚 / 经营异常 / 股权冻结 / 异常频繁的重要工商变更 | 普通地址变更、法定代表人变更 |
| 司法风险 | 被执行 / 被告重大诉讼 / 限制消费 / 股权冻结 / 大额未决案件 | 原告身份诉讼（不自动作为负面） |
| 舆情风险 | 负面舆情、对经营信用合规有实际影响的舆情、未核实但值得关注的负面信号 | 正面/中性舆情逐条罗列 |
| 财务风险与经营趋势 | 营收明显下降 / 净利润持续下降或转负 / 现金流恶化 / 负债率上升 / 审计意见异常 | 完整三年财务数据表展示 |
| 招聘与经营活动信号 | 招聘冻结 / 招聘收缩 / 大规模岗位撤回 / 招聘与风险明显矛盾 | 正常招聘活动逐岗位罗列 |

**低风险企业（Case D）的第二章：**
- 如果 material_risk_count == 0（自身无显著风险），本节只保留一段简洁结论
- 示例："经工商、司法、舆情、财务及招聘等多源信息交叉核查，当前未发现需要单独列示的企业自身实质性风险。现有工商变更属于正常管理调整，财务及经营活动信号总体稳定。"
- 然后直接进入第三章

**正常信号的处理：**
- 正常信号（财务稳定、招聘扩张、正面/中性舆情）不得在第二章逐项展开
- 只有具备实质缓释意义时才写入第五章

### 3.2 第三章：关联企业及风险传导

只写与目标企业风险判断有关的关联企业。每个关联风险必须包含：

```
### 3.x {关联企业名称}（{company_id}）

关系路径：
{company_id_a} → Rxxx → {company_id_b} → Rxxx → {target_company_id}

风险发现：
{风险事实描述}
（{Evidence ID 列表}）

风险传导判断：
{传导判断}
```

**传导表述规则：**
- 关联企业风险 ≠ 风险已经传导至目标企业
- 仅当证据充分时，方可表述风险传导
- 一般表述为"存在关联风险暴露"而非"风险已传导"

### 3.3 第六章：综合风险判断

第六章必须包含以下确定性注入字段（由 report_postprocessor 自动注入）：

```markdown
## 六、综合风险判断

综合风险等级：
{comprehensive_risk.level}

风险评分：
{comprehensive_risk.score}

风险模式：
{comprehensive_risk.case}（{case_label}）

风险解释：
{comprehensive_risk.explanation}

核心判断：
{LLM 生成的 1-3 段总结，涵盖自身风险、关联风险、多源信号、风险传导边界}

主要关注事项：
1. ...
2. ...
3. ...

建议继续关注：
1. ...
2. ...

不要提供投资买卖建议。
不要替代专业法律、审计或授信决策。
```

**注意：** 综合风险等级、风险评分、风险模式、风险解释四个字段由后端确定性注入，LLM 在生成报告时应预留占位空间（使用 `{risk_level}` 等占位符或空行），postprocessor 会自动替换。

## 4. Own Risk / Relationship Exposure / Comprehensive Risk 三层关系

### 4.1 三层定义

| 层级 | 字段名 | 语义 | 问的问题 | 数据来源 |
|------|--------|------|----------|----------|
| 第一层 | own_risk | 自身风险 | "企业自身有多危险？" | Rule Engine（仅企业自身 evidence） |
| 第二层 | relationship_exposure | 传导风险 | "因为关联关系，被动承受了多少风险？" | Transmission Engine（关联企业 own_risk + 关系图） |
| 第三层 | comprehensive_risk | 综合风险 | "整体风险状况如何？" | Fusion Engine（own_risk + exposure 融合） |

### 4.2 数据流向

```
Rule Engine (C001 的自身 evidence)
  → own_risk: { score, level, hard_rule_hits }
       │
       ├──→ Exposure Engine (C001 的关联企业 own_risk + R001-R010)
       │      → relationship_exposure: { score, level, company_contributions }
       │            │
       │            └──→ Fusion Engine (own_risk + exposure)
       │                   → comprehensive_risk: { score, level, case, explanation }
       │                        │
       │                        └──→ report_postprocessor → report_final.md
       │
       └──→ API response.risk_level = comprehensive_risk.level
```

### 4.3 不变量

| ID | 不变量 | 说明 |
|----|--------|------|
| I-1 | `comprehensive_risk.score >= own_risk.score` | 综合风险不低于自身风险 |
| I-2 | `comprehensive_risk.score >= exposure.score` | 综合风险不低于传导风险 |
| I-3 | 硬规则命中 → `comprehensive_risk.level == own_risk.level` | 硬规则不降级 |
| I-4 | `own=0 AND exposure=0 → comprehensive=0` | 双零则零 |
| I-5 | `case` 由 `own_is_high` 和 `exposure_is_high` 唯一确定 | Case 判定确定性 |

### 4.4 在报告中的体现

- **第一章**：展示 `comprehensive_risk.level`（综合风险等级）
- **第二章**：展示 own_risk 的具体风险事实和 evidence
- **第三章**：展示 relationship_exposure 的关联风险和传导路径
- **第四章**：综合分析三层风险的交叉验证
- **第六章**：展示 comprehensive_risk 的完整结果（等级、评分、Case、解释）

## 5. Evidence 引用规则

### 5.1 Evidence ID 格式

```
{数据源代号}{三位数字编号}
```

示例：B011、J008、R007、P012、F019、H003

### 5.2 引用位置

| 章节 | 引用方式 | 示例 |
|------|----------|------|
| 第二章 | 风险事实后括号内 | "C007 存在 2 条行政处罚记录（B011、B012）。" |
| 第三章 | 风险发现后括号内 | "（B011、J008、J010）" |
| 第五章 | 缓释信号后括号内 | "财务指标显示经营现金流仍为正（F019）。" |
| 第八章 | 独立列表 | "- B011 —— C007经营异常" |

### 5.3 第八章：关键证据引用

**选择标准：** 只列真正支撑最终风险判断的 Evidence。

**禁止：**
- 把所有查询到的 Evidence 全部放入
- 放入未参与风险判断的 Evidence
- 放入仅被查询但未被引用的 Evidence

**格式：**

```markdown
## 八、关键证据引用

- B011 —— C007经营异常
- J008 —— C007被执行
- J010 —— C007限制消费
- R007 —— C006持有C007 70%股权
- P012 —— C007负面舆情
- F019/F020/F021 —— C007经营现金流趋势
```

### 5.4 Evidence 与风险层级的对应

| Evidence 所属 | 贡献到哪一层 | 在报告哪个章节引用 |
|---------------|-------------|-------------------|
| 企业自身 B/J/F/P/H | own_risk | 第二章、第八章 |
| 关联企业的 own_risk | relationship_exposure | 第三章、第八章 |
| 关系 R | relationship_exposure | 第三章 |

## 6. Process 与 Final Report 分离

### 6.1 分离原则

Agent 的全部过程信息**绝不进入**最终报告。

| 内容 | 归属 | 说明 |
|------|------|------|
| 调查过程、阶段提示、todo/task | Investigation Trace | 不进入报告 |
| Coverage 检查结果 | Investigation Trace | 不进入报告 |
| Verifier 审核结果 | Investigation Trace | 不进入报告 |
| 中间思考、推理链 | Investigation Trace | 不进入报告 |
| 最终报告正文 | Final Report | 唯一输出物 |

### 6.2 确定性边界标记

最终报告在对话中输出时必须使用确定性边界：

```
FINAL_REPORT_BEGIN
# 企业关联风险调查报告
...
FINAL_REPORT_END
```

- `report_final.md` 持久化时只提取两标记之间的 Markdown
- `report_final.md` 第一行有效内容必须是 `# 企业关联风险调查报告`
- 标记外出现"正在…""下一步…""送审…"等过程语言，均视为污染

### 6.3 过程语言的定义

以下内容属于过程语言，禁止出现在 FINAL_REPORT_BEGIN / FINAL_REPORT_END 之间：

- "正在调查…"
- "下一步将…"
- "送审中…"
- "Coverage 检查结果：…"
- "Verifier 审核结果：…"
- "todo: …"
- "task: …"
- 任何以 "我" 开头的主观叙述

## 7. 低风险企业输出规范

### 7.1 适用场景

Case D（低风险）：own_risk.score < 50 且 exposure.score < 50，无风险传染通道。

### 7.2 第一章：风险结论摘要

```markdown
## 一、风险结论摘要

调查对象：
{company_name}（{company_id}）

分析版本：
v2-multisource

数据源：
工商、司法、企业关系、舆情、财务、招聘

综合风险等级：
低风险

风险结论：
经多源数据交叉核查，当前未发现需要单独列示的实质性风险。
现有工商变更属于正常管理调整，财务及经营活动信号总体稳定。

主要风险来源：
- 暂未发现具有实质影响的风险来源

缓释/相反信号：
- 财务指标总体稳定
- 招聘活动保持正常
- 关联网络清洁
```

### 7.3 第二章：企业自身主要风险

```markdown
## 二、企业自身主要风险

经工商、司法、舆情、财务及招聘等多源信息交叉核查，
当前未发现需要单独列示的企业自身实质性风险。
现有工商变更属于正常管理调整，财务及经营活动信号总体稳定。
```

**注意：** 不生成任何二级小节。直接进入第三章。

### 7.4 第三章：关联企业及风险传导

```markdown
## 三、关联企业及风险传导

经关系图谱分析，目标企业的关联企业当前无显著风险暴露。
（或：虽存在关联企业，但其风险水平较低，不构成实质性传导风险。）
```

### 7.5 第六章：综合风险判断

```markdown
## 六、综合风险判断

综合风险等级：
低风险

风险评分：
{comprehensive_risk.score}

风险模式：
D（低风险）

风险解释：
{comprehensive_risk.explanation}

核心判断：
目标企业自身经营状况稳定，关联网络清洁，综合风险评级为低风险。
当前无需要特别关注的风险事项。

主要关注事项：
1. 持续关注关联企业经营变化
2. 关注行业整体趋势

建议继续关注：
1. 关联企业的财务和司法动态
2. 行业政策变化
```

## 8. 高风险企业输出规范

### 8.1 适用场景

- Case A（双重风险）：own_risk.score >= 50 且 exposure.score >= 50
- Case B（传染风险）：own_risk.score < 50 但 exposure.score >= 50 或存在风险传染通道
- Case C（孤立风险）：own_risk.score >= 50 但 exposure.score < 50
- 硬规则命中（HR001-HR004）：无论 exposure 如何，comprehensive_level = own_risk.level

### 8.2 第一章：风险结论摘要

```markdown
## 一、风险结论摘要

调查对象：
{company_name}（{company_id}）

分析版本：
v2-multisource

数据源：
工商、司法、企业关系、舆情、财务、招聘

综合风险等级：
{comprehensive_risk.level}

风险结论：
{1-2 段概括本次最重要的风险发现，回答"有什么风险、主要来自哪里"}
```

**风险结论的写作要求：**
- 必须明确指出风险来源（自身 / 关联 / 双重）
- 必须引用关键 Evidence ID
- 不要在此处罗列企业基本档案
- 不要在此处展开财务数据表

### 8.3 第二章：企业自身主要风险

高风险企业的第二章应根据实际风险类别动态生成二级小节。

**Case A（双重风险）的典型结构：**
```markdown
## 二、企业自身主要风险

### 2.1 司法风险
{被执行、失信被执行、限制消费等}
（J008、J010）

### 2.2 财务风险与经营趋势
{营收下降、现金流恶化、负债率上升等}
（F019、F020、F021）

### 2.3 工商与经营风险
{行政处罚、经营异常等}
（B011）
```

**Case B（传染风险）的典型结构：**
- 第二章应较简短（自身风险低）
- 重点在第三章（关联风险传导）

**Case C（孤立风险）的典型结构：**
- 第二章应详细（自身风险高）
- 第三章应较简短（关联风险低）

### 8.4 第六章：综合风险判断

```markdown
## 六、综合风险判断

综合风险等级：
{comprehensive_risk.level}

风险评分：
{comprehensive_risk.score}

风险模式：
{comprehensive_risk.case}（{case_label}）

风险解释：
{comprehensive_risk.explanation}

核心判断：
{1-3 段总结：自身风险 + 关联风险 + 多源信号 + 风险传导边界}

主要关注事项：
1. {最紧急的风险事项}
2. {次紧急的风险事项}
3. {需要关注的趋势性风险}

建议继续关注：
1. {短期关注事项}
2. {中期关注事项}

不要提供投资买卖建议。
不要替代专业法律、审计或授信决策。
```

## 9. Case A/B/C/D 展示规则

### 9.1 Case 在报告中的展示位置

| Case | 第一章 | 第二章 | 第三章 | 第六章 |
|------|--------|--------|--------|--------|
| A（双重风险） | 综合等级 + 结论 | 详细（自身高风险） | 详细（关联高风险） | 完整展示 |
| B（传染风险） | 综合等级 + 结论 | 简短（自身低风险） | 详细（关联高风险） | 完整展示 |
| C（孤立风险） | 综合等级 + 结论 | 详细（自身高风险） | 简短（关联低风险） | 完整展示 |
| D（低风险） | 综合等级 + 结论 | 一段话（无显著风险） | 一段话（无显著暴露） | 完整展示 |

### 9.2 Case 在第六章的固定格式

```markdown
风险模式：
{case}（{case_label}）
```

其中 case_label 的映射：

| Case | case_label |
|------|------------|
| A | 双重风险 |
| B | 传染风险 |
| C | 孤立风险 |
| D | 低风险 |

### 9.3 Case 与章节数量的关系

| Case | 第二章二级小节数 | 第三章关联企业数 | 报告总长度预期 |
|------|-----------------|-----------------|---------------|
| A | 2-4 个 | 2-3 个 | 较长（1500-2500字） |
| B | 0-1 个 | 1-2 个 | 中等（1000-1800字） |
| C | 2-4 个 | 0-1 个 | 中等（1000-1800字） |
| D | 0 个 | 0 个 | 较短（600-1000字） |

### 9.4 硬规则覆盖的展示

当 own_risk 包含硬规则命中（HR001-HR004）时：

- 风险模式仍显示 Case A/B/C/D（由 Fusion Engine 判定）
- 但综合风险等级 = own_risk.level（不降级）
- 风险解释中应提及硬规则命中

示例：
```markdown
风险模式：
C（孤立风险）

风险解释：
企业自身风险极高（300分，高风险，命中硬规则 HR002 失信被执行），
关联企业风险传导极低（1分）。风险集中在企业自身经营/财务/司法问题。
```

## 10. 禁止事项

### 10.1 报告内容禁止

| # | 禁止内容 | 理由 |
|---|----------|------|
| 1 | 罗列企业完整工商档案 | 非风险导向 |
| 2 | 展示完整三年财务数据表 | 应提炼趋势，不展示原始数据 |
| 3 | 逐条罗列所有舆情 | 只写与风险判断相关的 |
| 4 | 逐岗位罗列所有招聘信息 | 招聘是弱信号，只写异常 |
| 5 | 为"凑完整"输出空章节 | 动态章节，无风险不生成 |
| 6 | 将原告身份自动作为负面 | 原告不等于风险 |
| 7 | 将未核实舆情当作事实 | 必须标注核实状态 |
| 8 | 将关联企业风险等同于已传导 | 传导需要证据支持 |
| 9 | 提供投资买卖建议 | 系统定位是风险洞察 |
| 10 | 替代专业法律、审计或授信决策 | 系统定位是辅助工具 |

### 10.2 报告格式禁止

| # | 禁止内容 | 理由 |
|---|----------|------|
| 1 | 使用非 `##` 的一级标题 | 一级标题必须用 `##` |
| 2 | 跳过任何一级章节 | 八个章节必须全部存在 |
| 3 | 调换一级章节顺序 | 顺序固定 |
| 4 | 在一级章节之间不使用 `---` | 保持视觉清晰 |
| 5 | 使用英文标题或中英混合 | 保持中文一致性 |

### 10.3 风险等级禁止

| # | 禁止内容 | 理由 |
|---|----------|------|
| 1 | LLM 自行指定风险等级 | 等级由后端确定性引擎计算 |
| 2 | LLM 自行指定风险评分 | 评分由后端确定性引擎计算 |
| 3 | LLM 自行指定 Case | Case 由 Fusion Engine 判定 |
| 4 | 报告中出现"风险等级：待填充" | postprocessor 自动注入 |
| 5 | 报告中出现"由 Risk Rule Engine 自动计算" | 过程语言，不应进入报告 |

### 10.4 过程语言禁止

| # | 禁止内容 | 归属 |
|---|----------|------|
| 1 | "正在调查…" | Investigation Trace |
| 2 | "下一步将…" | Investigation Trace |
| 3 | "送审中…" | Investigation Trace |
| 4 | "Coverage 检查结果：…" | Investigation Trace |
| 5 | "Verifier 审核结果：…" | Investigation Trace |
| 6 | "todo: …" / "task: …" | Investigation Trace |
| 7 | 任何以"我"开头的主观叙述 | Investigation Trace |

### 10.5 Evidence 引用禁止

| # | 禁止内容 | 理由 |
|---|----------|------|
| 1 | 把所有查询到的 Evidence 全部放入第八章 | 只列支撑判断的 |
| 2 | 放入未参与风险判断的 Evidence | 误导读者 |
| 3 | Evidence ID 格式不规范 | 必须为 `{代号}{三位数字}` |
| 4 | 在第八章重复第二/三章已引用的 Evidence | 第八章是汇总，不是重复 |
